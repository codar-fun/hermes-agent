# 08 · 定时任务与自动化

Hermes 内置 cron 调度器，可以**用自然语言**安排定时/周期任务，无人值守地运行，并把结果投递到任意消息平台。典型场景：每日报告、夜间备份、每周审计。

---

## 1. 管理定时任务

### CLI

```bash
hermes cron              # 管理定时任务
hermes cron list         # 列出所有任务
hermes cron status       # 调度器是否在运行
```

### 会话内 / 工具

```text
/cron                    # 管理定时任务
```

智能体也能用 **`cronjob` 工具**（`tools/cronjob_tools.py`）来创建/列出/更新/暂停/恢复/删除/触发任务——也就是说你可以直接对它说「每天早上 8 点给我发一份昨天的 GitHub 动态摘要」，它会帮你建好定时任务。

---

## 2. 调度器怎么跑

- 任务定义在 `cron/jobs.py`，调度逻辑在 `cron/scheduler.py`。
- **网关每 60 秒调用一次 `tick()`**，检查并运行到期任务。
- 用文件锁（`~/.hermes/cron/.tick.lock`）保证多进程重叠时同一时刻只有一个 tick 在跑。
- 任务定义存在 `~/.hermes/cron/`。

> 因此：要让定时任务真正触发，**需要网关在运行**（`hermes gateway start`）。`hermes cron status` 可确认调度器状态。

---

## 3. 投递到平台

每个任务可指定投递目标（某平台），结果会送到该平台的 **Home 频道**：

1. 先在目标聊天里设 Home 频道（见 [05 · 消息网关与平台连接](./05-消息网关与平台连接.md)）：

   ```text
   /sethome
   ```

   或手动设环境变量，如 `TELEGRAM_HOME_CHANNEL=123456789`、`SLACK_HOME_CHANNEL=C123...`。

2. 任务运行后通过实时适配器投递；若未设 Home 频道则报错并提示用 `/sethome`。

```yaml
# config.yaml
cron:
  wrap_response: true        # 是否包裹/格式化投递内容
  max_parallel_jobs: null    # 并行任务上限（null = 不限）
```

---

## 4. 时区与调度表达式

- 调度基于 `croniter`（标准 cron 表达式），也支持间隔（interval）任务。
- 时区处理依赖系统 tzdata；Windows 通过打包的 `tzdata` 数据包补齐（Linux/macOS 用系统 `/usr/share/zoneinfo`）。
- 创建任务时用自然语言描述时间，智能体会转换成对应的 cron 表达式。

---

## 5. 典型自动化示例

对智能体说（中文/英文均可），它会建好相应定时任务并投递到你的 Home 频道：

- 「每天早上 9 点，汇总我关注的几个 GitHub 仓库昨天的 PR 和 issue，发到 Telegram。」
- 「每周一上午，巡检服务器磁盘和服务状态，有异常就告警。」
- 「每晚 2 点，把工作目录里的项目备份到远程，并发一条完成通知。」

这些任务会作为独立的智能体会话运行，拥有完整工具能力（终端、文件、网页、`send_message` 等）。

> 提示：定时任务派生子进程时需要正确传递 `HERMES_HOME`，否则可能落到错误的 Profile。多 Profile 用户尤其注意（见 [03 · 配置详解](./03-配置详解.md)）。

---

## 6. 进阶：Kanban 多 Profile 协作

除了 cron，Hermes 还内置多智能体协作看板，用于把大任务分解给多个 Profile 并行推进：

```text
/kanban           # 多 Profile 协作看板（任务、依赖链接、评论）
```

```yaml
kanban:
  dispatch_in_gateway: true
  dispatch_interval_seconds: 60
  orchestrator_profile: ""     # 负责任务分解的 Profile
  auto_decompose: true
```

相关 CLI：`hermes kanban ...`（分解、规划、诊断等子命令）。
