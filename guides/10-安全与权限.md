# 10 · 安全与权限

Hermes 能执行命令、读写文件、上网、发消息——所以它在多个层面做了安全设计。本文汇总用户需要了解的权限与安全机制。

---

## 1. 危险命令审批

默认情况下，可能造成破坏的命令（删除、覆盖、对外发送等）会先**请求批准**，再执行。

```text
/approve       # 批准待处理的危险命令
/deny          # 拒绝
```

- 审批可由便宜的辅助模型快速决策（`auxiliary.approval`，见 [04 · 模型与提供商](./04-模型与提供商.md)）。
- 审批模式与命令白名单跟随 Profile；从 OpenClaw 迁移时会导入命令白名单。

### YOLO 模式 ⚠

```text
/yolo          # 切换 YOLO 模式：跳过所有危险命令审批
```

YOLO 模式下不再询问，请仅在可信、隔离的环境使用。

### 子智能体审批

```yaml
delegation:
  subagent_auto_approve: false   # false=拒绝危险命令，true=自动批准
```

## 2. 沙箱与隔离

把命令执行放进隔离环境，是限制「智能体能搞坏什么」的最有效手段：

- **终端后端**（见 [06 · 工具与终端后端](./06-工具与终端后端.md)）：用 `docker` / `modal` / `daytona` / `singularity` 把执行关进容器或云沙箱，而非直接跑在宿主机。
- **`execute_code` 沙箱**：受限工具集 + 资源限制（超时、调用次数、输出大小上限），且过滤掉密钥环境变量。
- **多 Profile 隔离**：不同用途用不同 Profile，配置/会话/技能/记忆互不可见（见 [03 · 配置详解](./03-配置详解.md)）。

---

## 3. 消息平台访问控制

谁能驱动你的 bot，由白名单或配对码控制（详见 [05 · 消息网关与平台连接](./05-消息网关与平台连接.md)）：

- `<平台>_ALLOWED_USERS`：静态白名单。
- **DM 配对码**：8 位验证码、1 小时有效、限流与失败锁定（`gateway/pairing.py`）。
- ⚠ `GATEWAY_ALLOW_ALL_USERS=true` / `<平台>_ALLOW_ALL_USERS=true` 放行所有人，仅限测试。
- 群里可用 `<平台>_REQUIRE_MENTION` 要求 @ 才回复。
- 用 `/whoami` 查看自己的斜杠命令权限（admin / user）；网关对斜杠命令有访问分级（`gateway/slash_access.py`）。

---

## 4. 密钥管理

- **密钥只放 `~/.hermes/.env`**（权限应受保护），非密钥设置放 `config.yaml`。
- `HERMES_HOME`、`HERMES_PROFILE`、`HERMES_CONFIG`、`HERMES_ENV` 不能通过仪表盘 env 写入器修改。
- OAuth 凭据（Nous / Anthropic / xAI / MiniMax 等）存 `~/.hermes/auth.json` 的凭据池，写盘前会剥离原始密钥值（`agent/credential_persistence.py`）。
- 工具错误信息会做净化：剥离 XML/CDATA/markdown 包裹并截断，避免把密钥或注入内容回传给模型。
- 可选接入外部密钥后端（如 Bitwarden Secrets Manager，`agent/secret_sources/`），只设置尚未存在的环境变量，非破坏式。
- **敏感路径拒写名单**（`agent/file_safety.py`）：`.ssh`、`.env`、`.aws`、`.kube` 等关键路径永不被写入；用户 @ 引用文件时也有敏感路径防护。

---

## 5. 技能与供应链安全

- **Skills Hub 审计**：安装第三方技能前做 AST 审计与隔离，记录来源锁与审计日志；信任分级 builtin/trusted/community；防路径穿越（见 [07 · 技能、记忆与学习闭环](./07-技能记忆与学习闭环.md)）。
- **依赖精确钉版本**：`pyproject.toml` 里每个直接依赖都钉死具体版本，供应商专属依赖惰性安装。这是针对供应链攻击（如 2026 年 5 月的 Mini Shai-Hulud 蠕虫）的加固——单个被投毒的 PyPI 版本不会波及所有新安装。修改依赖前请先读 `pyproject.toml` 里的长注释。
- 仓库内置 OSV 扫描、供应链审计等 CI（`.github/workflows/`）。

---

## 6. 检查点与回滚

防止误操作造成不可逆损失：

```text
/rollback      # 列出/恢复文件系统检查点
/snapshot      # 创建/恢复 Hermes 配置状态快照
```

```yaml
checkpoints:
  enabled: false          # 开启后文件操作前自动快照
  max_snapshots: 20
  max_total_size_mb: 500
```

- Curator 运行前也会把技能树打包快照，可回滚（见文档 07）。

---

## 7. 隐私

- 网关日志对用户/聊天 ID 做哈希脱敏；部分平台（如 SMS）标记 `pii_safe`，会从会话描述里抹去电话号。
- 用 `/insights`、`hermes logs` 时数据均来自本地（`state.db`、`~/.hermes/logs/`），不外发。

---

## 安全自查清单

- [ ] 生产/不可信场景：用 Docker/云沙箱后端，别用 `local`；不要开 YOLO。
- [ ] 消息平台：用 `ALLOWED_USERS` 白名单或配对码，别用 `ALLOW_ALL`。
- [ ] 密钥只进 `.env`，确认文件权限；考虑接外部密钥后端。
- [ ] 高风险操作开启 `checkpoints`。
- [ ] 安装第三方技能/MCP 只用可信来源，注意 Skills Hub 的信任分级。
- [ ] 多用途隔离用不同 Profile。
