# 05 · 消息网关与平台连接

消息网关（gateway）是一个常驻进程，让你**从 Telegram / Discord / Slack / WhatsApp / Signal / 飞书 / 钉钉 等平台直接跟 Hermes 对话**，而不必守着终端。一个网关进程可同时服务多个平台。

---

## 1. 网关生命周期

```bash
hermes gateway setup       # 交互式配置要启用哪些平台（填 Token 等）
hermes gateway             # 前台运行（开发/调试，看实时日志）
hermes gateway start       # 后台启动为服务
hermes gateway status      # 查看存活状态与 PID
hermes gateway restart     # 排空活跃任务后优雅重启
hermes gateway stop        # 停止
hermes gateway logs        # 查看网关日志
hermes gateway install     # 安装为系统服务（开机自启）
hermes gateway uninstall   # 卸载系统服务
```

作为服务运行时：

- **Linux**：systemd 用户级（或系统级）服务
- **macOS**：launchd agent（`~/Library/LaunchAgents/` 下的 .plist）
- **Windows**：手动进程，或 WSL2 + systemd

> 网关运行时会读取 `config.yaml`（直接读原始 YAML）与 `.env`。会话存入 `state.db`，日志在 `~/.hermes/logs/gateway.log`。

## 2. 各平台连接凭据

用 `hermes gateway setup` 向导填写最省事（会引导你拿 Token 并写入 `.env`）。下面列出**核对自源码的真实环境变量名**，方便手动配置。

通用约定（几乎所有平台都有）：

- `<平台>_ALLOWED_USERS`：逗号分隔的用户 ID 白名单
- `<平台>_HOME_CHANNEL`：定时任务/通知的默认投递频道
- `<平台>_REQUIRE_MENTION`：群里是否需要 @ 才回复
- `GATEWAY_ALLOW_ALL_USERS=true`：放行所有用户（仅开发测试用）⚠

### Telegram

```bash
TELEGRAM_BOT_TOKEN=...           # 从 @BotFather 获取
TELEGRAM_ALLOWED_USERS=123,456   # 允许的用户 ID
# 可选 webhook 模式：
TELEGRAM_WEBHOOK_URL=...
TELEGRAM_WEBHOOK_SECRET=...
```

### Discord

```bash
DISCORD_BOT_TOKEN=...
DISCORD_ALLOWED_USERS=...
DISCORD_ALLOWED_CHANNELS=...
DISCORD_ALLOWED_ROLES=...
DISCORD_REQUIRE_MENTION=true
DISCORD_AUTO_THREAD=...           # 自动开线程等行为
```

> Discord 适配器以插件形式存在（`plugins/platforms/discord/`），其工具 schema 会按 bot 的 intents（如 MESSAGE_CONTENT）动态调整。

### Slack

```bash
SLACK_BOT_TOKEN=xoxb-...          # Bot Token
SLACK_APP_TOKEN=xapp-...          # App-Level Token（Socket Mode）
SLACK_ALLOWED_USERS=U123,U456
```

### Signal

```bash
SIGNAL_GROUP_ALLOWED_USERS=...

```

### Matrix

```bash

MATRIX_ACCESS_TOKEN=...           # 推荐用 access token
# 或用账号密码登录：
```

### Email（邮件）

## 3. 用户授权：白名单 vs 配对

谁能跟你的 bot 说话，由两套机制控制：

### 方式一：静态白名单

直接设 `<平台>_ALLOWED_USERS=user1,user2,...`（逗号分隔的用户 ID / 地址），列表内的人直接放行。

### 方式二：DM 配对码（`gateway/pairing.py`）

未知用户私聊 bot 时，可走基于验证码的审批流程：

- **验证码**：8 位（无歧义字母表，去掉 0/O/1/I），有效期 1 小时
- **限流**：每用户每 10 分钟 1 次请求；每平台最多 3 个待处理；5 次失败锁定 1 小时
- **存储**：`~/.hermes/pairing/{平台}-pending.json` 与 `{平台}-approved.json`（权限 0600）

管理员审批：在会话里用 `/approve <码>` / `/deny`，或用 CLI 侧的配对命令查看/批准待处理请求。

> ⚠ `GATEWAY_ALLOW_ALL_USERS=true` 或某平台的 `<平台>_ALLOW_ALL_USERS=true` 会放行所有人——仅限可信测试环境。

## 4. Home 频道与定时投递

**Home 频道**是定时任务结果和主动通知的默认去处。

设置方法：

```text
# 在想要接收通知的聊天里直接发：
/sethome
```

网关会记下该聊天 ID 并保存为 `<平台>_HOME_CHANNEL`。也可手动设：

```bash
TELEGRAM_HOME_CHANNEL=123456789      # Telegram 用户/群 ID
SLACK_HOME_CHANNEL=C1234567890       # Slack 频道 ID
FEISHU_HOME_CHANNEL=oc_abcdef        # 飞书会话 ID
```

定时任务（cron）投递到某平台时会送到其 Home 频道；若未设置则报错并提示用 `/sethome`。详见 [08 · 定时任务与自动化](./08-定时任务与自动化.md)。

## 5. 跨平台与流式

- **`send_message` 工具**：智能体可主动向任意平台/对象发消息（文本、图片、视频、语音）。
- **流式渐进编辑**：网关把同步智能体的输出桥接成平台上的渐进消息编辑（`gateway/stream_consumer.py`），支持 Telegram/Discord/Slack 的就地编辑、Telegram 私聊原生草稿流式等。可用 `config.yaml` 的 `streaming.enabled` 控制。
- **会话自动重置**：`session_reset.mode`（both/idle/daily/none）与 `idle_minutes` 控制空闲/每日自动开新会话。
- **`/handoff`**：把 CLI 当前会话移交到某消息平台继续。
