# 13 · 工具与终端后端详解

这是 [06 · 工具与终端后端](./06-工具与终端后端.md) 的深度补充：工具集完整目录、文件/网页/terminal/execute_code 工具的参数与限制、**六种终端后端逐一的精确配置键**、委派子智能体、工具输出限制。

> 所有工具名、工具集名、配置键、默认值、环境变量均核对自源码（`toolsets.py`、`tools/*.py`、`tools/environments/*`、`hermes_cli/config.py`）。

---

## 1. 工具系统总览

- **声明式注册**：每个 `tools/*.py` 在导入时调用 `registry.register(...)` 自注册（`tools/registry.py`）。`ToolEntry` 含 `name`、`toolset`、`schema`、`handler`、`check_fn`（可用性探测）、`max_result_size_chars` 等。
- **可用性门控**：`check_fn` 探测外部条件（Docker 是否在跑、HASS_TOKEN 是否存在、Playwright 是否装好），结果缓存 30 秒（`_CHECK_FN_TTL_SECONDS=30.0`）。不满足条件的工具不会暴露给模型。
- **渐进式披露**：非核心（MCP/插件）工具超出预算时，藏到 `tool_search`/`tool_describe`/`tool_call` 桥接背后。
- **暴露 = 进工具集**：自动发现只注册 schema；工具名必须出现在某个工具集里才会真正给到智能体。

```text
/tools list                  # 当前可用工具
/tools enable|disable <名>   # 启用/禁用
/toolsets                    # 列出工具集
hermes tools                 # 交互式配置
```

## 3. 文件工具

| 工具 | 关键参数 | 说明 |
|------|----------|------|
| `read_file` | `path`、`offset`、`limit` | 分页读；阻止读设备文件（`/dev/zero`、`/dev/random`、`/dev/stdin` 等会卡死/无限输出的路径）与二进制 |
| `write_file` | `path`、`content` | 写前做敏感路径检查（`~/.ssh/`、`~/.hermes/.env`、`/etc/`、项目 `.env`/`config.yaml` 等）；写后可触发 LSP 诊断反馈 |
| `patch` | 见下 | 模糊匹配补丁，支持两种模式 |
| `search_files` | `root`、`pattern`、`limit` | 基于 ripgrep 的内容/文件名搜索 |

`patch` 两种模式：

- **replace 模式**：`old_string`（带上下文模糊匹配）→ `new_string`，可选 `replace_all`。
- **V4A patch 模式**：多文件 `*** Update/Add/Delete File: <路径>` + diff hunk。

**读取上限**：`config.yaml` 顶层 `file_read_max_chars`（默认 100,000；进程内首次读取后缓存）。

## 4. 网页工具

`web_search` / `web_extract` 后端可配，未指定则按可用 Key 自动探测：

```yaml
web:
  backend: "firecrawl"          # 搜索+抽取的共同兜底
  search_backend: "firecrawl"   # 单独指定搜索后端（覆盖 backend）
  extract_backend: "firecrawl"  # 单独指定抽取后端
```

可选后端与对应 Key：`firecrawl`（`FIRECRAWL_API_KEY`）、`parallel`（`PARALLEL_API_KEY`）、`tavily`（`TAVILY_API_KEY`）、`exa`（`EXA_API_KEY`）、`searxng`（`SEARXNG_URL`）、`brave`（`BRAVE_SEARCH_API_KEY`）、`ddgs`（DuckDuckGo，无需 Key）、`xai`。自动探测优先级：Firecrawl → Parallel → Tavily → Exa → SearXNG → Brave → DDGS。

> Nous Portal 订阅用户的 Firecrawl 会经工具网关路由，无需单独申请。

## 5. `terminal` 工具

执行 shell 命令。主要参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `command` | — | 要执行的命令 |
| `background` | `false` | 后台运行（返回 session_id/pid）|
| `timeout` | `terminal.timeout`(180) | 超时秒数；前台上限 600（`TERMINAL_MAX_FOREGROUND_TIMEOUT`）|
| `workdir` | — | 覆盖工作目录（校验后）|
| `pty` | `false` | 伪终端（交互式工具，仅 local）|
| `notify_on_complete` / `watch_patterns` | — | 后台进程完成通知 / 监视输出关键字 |

- **超时**：到时返回 exit_code 124 并追加 `[Command timed out after Xs]`。
- **中断**：用户打断时向进程组发 SIGINT/SIGTERM（exit_code 130）。
- **危险命令**：触发审批流程（见 [10 · 安全与权限](./10-安全与权限.md)）。
- 后台进程用 `process` 工具或 `/stop` 管理。

## 6. `execute_code` 工具（RPC 流水线）

让模型写一段 Python，通过 RPC 调用受限工具集，把多步流水线收敛成一次回合。

- **可调用的工具**（`SANDBOX_ALLOWED_TOOLS`，与会话启用集取交集）：

  ```
  web_search, web_extract, read_file, write_file, search_files, patch, terminal
  ```

- **RPC 通道**：本地走 Unix domain socket；远程后端（Docker/SSH/Modal/…）走基于文件的 RPC。
- **资源限制**（可在 `config.yaml` 的 `code_execution.*` 覆盖）：

  | 常量 | 默认 | 含义 |
  |------|------|------|
  | `code_execution.timeout` | 300 | 脚本超时（秒）|
  | `code_execution.max_tool_calls` | 50 | 脚本内最多 RPC 工具调用次数 |
  | `MAX_STDOUT_BYTES` | 50,000 | stdout 上限（超出取 40% 头 + 60% 尾）|

- **环境过滤**：脚本环境会剥离含 `KEY`/`TOKEN`/`SECRET`/`PASSWORD`/`CREDENTIAL`/`AUTH` 等子串的变量；只放行安全前缀（`PATH`/`HOME`/`LANG`/`XDG_*`/`PYTHONPATH` 等）+ 显式 `env_passthrough` 声明的变量。
- **迭代退还**：因超时/中断未完成的工具调用会退还 1 个迭代额度。

## 7. 终端后端逐一详解

后端由 `config.yaml` 的 `terminal.backend` 选择。所有后端共享 spawn-per-call 模型：首条命令用登录 shell 抓一次环境快照（env/函数/别名），之后每条命令前重新 source；跨命令保持 CWD；每 10 秒向网关发活动心跳；超时杀进程。

通用键（所有后端）：`backend`、`cwd`（默认 `.`）、`timeout`（180）、`persistent_shell`（true）、`env_passthrough`（[]）。

### local（本地，默认）

```yaml
terminal:
  backend: "local"
  cwd: "."
  timeout: 180
  env_passthrough: []          # 额外透传的环境变量名
  auto_source_bashrc: true     # 自动 source ~/.profile / ~/.bashrc
```

相关环境变量：`TERMINAL_CWD`（覆盖工作目录）、`TERMINAL_LOCAL_PERSISTENT`、Windows 上 `HERMES_GIT_BASH_PATH`。直接访问宿主文件系统，无文件同步。

### docker（容器，推荐用于隔离）

```yaml
terminal:
  backend: "docker"
  docker_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  docker_forward_env: []                 # 转发的宿主环境变量名（如 ["SSH_AUTH_SOCK"]）
  docker_env: {}                         # 显式注入容器的环境变量
  docker_volumes: []                     # 绑定挂载 ["宿主路径:容器路径", ...]
  docker_mount_cwd_to_workspace: false   # 把当前目录挂到 /workspace
  docker_run_as_host_user: false         # 以宿主 uid:gid 运行
  docker_extra_args: []                  # 额外 docker run 参数
  docker_persist_across_processes: true  # 跨 Hermes 重启复用容器
  container_cpu: 1                       # CPU 限制
  container_memory: 5120                 # 内存 MB（默认 5GB）
  container_disk: 51200                  # 磁盘 MB（默认 50GB）
  container_persistent: true             # 跨会话保留 /workspace 与 /root
```

环境变量：`HERMES_DOCKER_BINARY`（指定 docker/podman 路径）。容器默认硬化：`--cap-drop ALL`（仅加回少量必要 cap）、`--security-opt no-new-privileges`、`--pids-limit 256`、`/tmp`/`/var/tmp` 挂 tmpfs。需 Docker 守护进程在跑。

### ssh（远程主机）—— ⚠ 用环境变量配置

SSH 后端的连接参数读自**环境变量**（不是 `config.yaml` 的 terminal 键）：

```bash
terminal.backend: "ssh"      # 这一项仍在 config.yaml 里设
# 以下放进 ~/.hermes/.env：
TERMINAL_SSH_HOST=example.com     # 必填：主机
TERMINAL_SSH_USER=ubuntu          # 必填：用户名
TERMINAL_SSH_PORT=22              # 端口，默认 22
TERMINAL_SSH_KEY=/path/to/key     # 私钥路径（留空则用 ssh-agent）
TERMINAL_SSH_PERSISTENT=1         # 保持连接复用
```

用 SSH ControlMaster 复用连接；CWD 通过 stdout 标记跟踪；通过 `FileSyncManager` 在每次命令前把 `~/.hermes/`（凭据、技能、缓存）同步到远端（见 §8）。

### modal / managed_modal（云沙箱，可休眠）

```yaml
terminal:
  backend: "modal"
  modal_mode: "auto"          # auto（探测）| direct（原生 SDK）| managed（经网关）
  modal_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  container_cpu: 1
  container_memory: 5120
  container_disk: 51200
  container_persistent: true  # 用快照持久化文件系统
```

- **direct 模式**：原生 Modal SDK，需 `MODAL_TOKEN_ID` + `MODAL_TOKEN_SECRET`；快照缓存在 `~/.hermes/modal_snapshots.json`。
- **managed 模式**：经 Nous 网关，需 Nous 用户令牌；网关托管沙箱生命周期。
- 空闲休眠、按需唤醒——闲时几乎零成本。

### daytona（云沙箱）

```yaml
terminal:
  backend: "daytona"
  daytona_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  container_cpu: 1
  container_memory: 5120
  container_disk: 10240       # Daytona 平台上限约 10GB
  container_persistent: true  # 清理时 stop（下次 resume）
```

环境变量：`DAYTONA_API_KEY`。按 `hermes-{task_id}` 命名复用沙箱；文件经 SDK 上传。

### singularity / apptainer（HPC 容器）

```yaml
terminal:
  backend: "singularity"
  singularity_image: "docker://nikolaik/python-nodejs:python3.11-nodejs20"  # 或 .sif 路径
  container_cpu: 1
  container_memory: 5120
  container_persistent: true   # 跨会话保留 overlay 目录
```

环境变量：`TERMINAL_SCRATCH_DIR`（overlay 暂存目录）、`APPTAINER_CACHEDIR`（SIF 缓存）、`TERMINAL_SANDBOX_DIR`。`docker://` 镜像首次会构建成 `.sif`（一次性，约数分钟）。硬化：`--containall --no-home`（不暴露宿主文件系统）。需 PATH 里有 `apptainer` 或 `singularity`。

### 文件同步（`file_sync.py`）

用于 **SSH / Modal / Daytona**（Docker/Singularity 用绑定挂载或 overlay，不走此路径）：

- 同步范围：`~/.hermes/` 下的凭据、技能、缓存。
- 限流：默认两次同步间隔 5 秒（`HERMES_FORCE_FILE_SYNC=1` 可强制）。
- 事务性：全部成功才提交；清理时回拉远端变更，只覆盖与推送时 SHA-256 不同的文件（避免覆盖宿主改动）。

## 8. 委派与子智能体（`delegate_task`）

派生隔离的子智能体跑并行工作流。

**子智能体永远禁用的工具**（`DELEGATE_BLOCKED_TOOLS`）：

```
delegate_task    # 不允许递归委派（除非 orchestrator 角色）
clarify          # 不与用户交互
memory           # 不写共享 MEMORY.md
send_message     # 不产生跨平台副作用
execute_code     # 子智能体应逐步推理，而非写脚本
```

配置（`config.yaml`）：

```yaml
delegation:
  max_concurrent_children: 3    # 并行子智能体上限（下限 1）
  max_spawn_depth: 1            # 嵌套深度；1=扁平（父→子）
  child_timeout_seconds: 600    # 每个子智能体超时（下限 30s）
  subagent_auto_approve: false  # 子智能体内危险命令：false=拒绝，true=自动批准
```

环境变量覆盖：`DELEGATION_MAX_CONCURRENT_CHILDREN`、`DELEGATION_MAX_SPAWN_DEPTH`、`DELEGATION_CHILD_TIMEOUT_SECONDS`。子智能体可申请大多数叶子工具集（不含 delegation/moa/safe/debugging 与平台工具集，除非 orchestrator 角色重新加回 delegation）。

## 9. 工具输出限制与持久化

三层防止上下文溢出（`tools/budget_config.py`、`tool_result_storage.py`、`tool_output_limits.py`）：

| 层 | 机制 | 默认 |
|----|------|------|
| 单工具截断 | 工具自身先截断（如 search_files）| — |
| 单结果持久化 | 超过 `max_result_size` 的结果写到 `/tmp/hermes-results/<id>.txt`，上下文里换成 `<persisted-output>` + 预览 + 路径 | `DEFAULT_RESULT_SIZE_CHARS=100,000` |
| 单回合总预算 | 一回合所有工具结果总量超预算时，把最大的结果溢出到磁盘 | `DEFAULT_TURN_BUDGET_CHARS=200,000` |

可调键：

```yaml
tool_output:
  max_bytes: 50000        # terminal 输出字符上限
  max_lines: 2000         # read_file 分页上限
  max_line_length: 2000   # 单行上限（超出标 ... [truncated]）
```

`read_file` 的持久化阈值被钉为无穷（防止 持久化→读→再持久化 的死循环）。

## 10. 危险命令审批（速记）

`terminal` 的危险命令会经审批（`tools/approval.py`）：

- **硬性禁止**（即使 YOLO 也拦）：`rm -rf /`、`mkfs`、写裸块设备、fork bomb、关机/重启、`sudo -S` 无密码管道等。
- **常规审批**：递归删除、`chmod 777`、无 WHERE 的 SQL 删除、改系统配置/`~/.ssh`/`~/.hermes`、`curl|sh`、`git reset --hard`/`push --force` 等。
- 配置：`approvals.mode`（`manual`/`smart`/`off`）、`approvals.timeout`、`approvals.cron_mode`、`command_allowlist`。
- 操作：`/approve`、`/deny`、`/yolo`。详见 [10 · 安全与权限](./10-安全与权限.md)。
