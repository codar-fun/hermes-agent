# 03 · 配置详解

Hermes 的配置分两个文件，职责分明：

| 文件 | 放什么 | 说明 |
|------|--------|------|
| `~/.hermes/config.yaml` | **所有非密钥设置** | 模型、终端、显示、记忆、压缩、定时任务等 |
| `~/.hermes/.env` | **只放密钥** | API Key、Token、密码 |

> 经验法则：超时、阈值、开关、路径、显示偏好 → 放 `config.yaml`；任何「秘密」→ 放 `.env`。
> 默认值来自 `hermes_cli/config.py` 的 `DEFAULT_CONFIG`；根目录的 `cli-config.yaml.example` 是带注释的完整示例。

修改后用 `hermes config set <点路径> <值>` 或直接编辑文件；用 `/reload` 可把 `.env` 重载进运行中的会话。

## 1. `config.yaml` 主要配置段

下面只列出**用户真正会改**的键。完整结构见 `cli-config.yaml.example`。

### `model` —— 当前模型

```yaml
model:
  provider: "nous"                       # 供应商 slug（见文档 04）
  model: "anthropic/claude-opus-4.8"     # 模型 ID
  base_url: ""                           # 留空则用供应商默认端点
  api_key: ""                            # 留空则读对应环境变量
fallback_providers:                      # 智能回退链
  - openrouter
  - anthropic
```

### `agent` —— 智能体行为

```yaml
agent:
  max_turns: 90                # 每会话最大工具调用轮数
  gateway_timeout: 1800        # 网关会话空闲超时（秒）
  api_max_retries: 3           # API 错误重试次数
  reasoning_effort: "medium"   # 推理强度：xhigh/high/medium/low/minimal/none
  image_input_mode: "auto"     # 用户图片呈现方式：auto/native/text
  task_completion_guidance: true
  personalities: {}            # 预定义人格（/personality 用）
```

### `terminal` —— 命令执行后端

```yaml
terminal:
  backend: "local"             # local/ssh/docker/singularity/modal/daytona
  cwd: "."                     # 工作目录（消息模式下尤其重要）
  timeout: 180                 # 命令超时（秒）
  persistent_shell: true       # 跨命令保持 shell 存活
  docker_image: "nikolaik/python-nodejs:python3.11-nodejs20"
  docker_mount_cwd_to_workspace: false
```

> **工作目录差异**：CLI 用进程当前目录（`os.getcwd()`）；消息模式用 `terminal.cwd`（网关会桥接成 `TERMINAL_CWD` 环境变量给子工具）。详见 [06 · 工具与终端后端](./06-工具与终端后端.md)。

### `compression` —— 上下文压缩

```yaml
compression:
  enabled: true
  threshold: 0.50          # 上下文用到 50% 时触发
  target_ratio: 0.20       # 压缩后保留约 20% 作为近期尾部
  protect_last_n: 20       # 始终保留最近 N 条消息
```

### `display` —— 显示

```yaml
display:
  skin: "default"          # 主题：default/ares/mono/slate
  interface: "cli"         # 默认启动界面：cli/tui
  language: "en"           # 界面语言：en/zh/ja/de/es/fr/tr/uk 等
  streaming: false         # 是否把 token 流式打到终端
  show_reasoning: false    # 是否显示模型思考
  tool_progress: "all"     # 工具活动可见度：off/new/all/verbose
  compact: false
  bell_on_complete: false
```

### `memory` —— 长期记忆

```yaml
memory:
  memory_enabled: true        # 智能体持久笔记（MEMORY.md）
  user_profile_enabled: true  # 用户画像（USER.md）
  memory_char_limit: 2200     # 笔记字符上限（约 800 token）
  user_char_limit: 1375       # 画像上限（约 500 token）
  nudge_interval: 10          # 每 N 回合提醒一次保存
```

### `skills` 与 `curator` —— 技能与自维护

```yaml
skills:
  creation_nudge_interval: 15   # 每 N 轮提醒一次创建技能
  external_dirs: []             # 额外只读技能目录
curator:
  enabled: true
  interval_hours: 168           # 每 7 天跑一次后台技能维护
  stale_after_days: 30          # N 天未用标记为 stale
  archive_after_days: 90        # N 天未用归档
```

### `delegation` —— 子智能体

```yaml
delegation:
  model: ""                    # 子智能体模型覆盖
  max_iterations: 50           # 每个子智能体的迭代预算
  max_concurrent_children: 3   # 并行子智能体数
  max_spawn_depth: 1           # 委派树深度（1=扁平，2+=嵌套）
  subagent_auto_approve: false
```

### `auxiliary` —— 辅助（侧）模型

为各类侧 LLM 任务单独指定供应商/模型（视觉、压缩、网页抽取、审批、标题生成等）：

```yaml
auxiliary:
  vision:
    provider: "auto"     # auto/openrouter/nous/anthropic/custom
    model: ""            # 留空用供应商默认
    timeout: 120
  compression:
    provider: "auto"
    model: ""
  web_extract:
    provider: "auto"
    timeout: 360
  approval:              # 审批决策，建议用便宜模型
    provider: "auto"
    model: ""
```

详见 [04 · 模型与提供商](./04-模型与提供商.md)。

### 其他常用段

```yaml
checkpoints:             # 文件操作前自动快照
  enabled: false
  max_snapshots: 20
tts:                     # 文字转语音
  provider: "edge"       # edge/elevenlabs/openai/xai/minimax/mistral/gemini/piper
stt:                     # 语音转文字
  enabled: true
  provider: "local"      # local/groq/openai/mistral/elevenlabs
cron:
  wrap_response: true
  max_parallel_jobs: null
gateway: {}              # 文件投递策略等
logging: {}              # 日志级别与轮转
```

## 2. `.env` —— 密钥

`.env` 只放 API Key / Token / 密码。可在 `hermes setup` 向导里填，或手动编辑。所有受支持的密钥都登记在 `hermes_cli/config.py` 的 `OPTIONAL_ENV_VARS` 里，按类别组织。

### 供应商 Key（部分）

```bash
OPENROUTER_API_KEY=...
ANTHROPIC_API_KEY=...
OPENAI_API_KEY=...
GOOGLE_API_KEY=...        # 或 GEMINI_API_KEY
XAI_API_KEY=...
DEEPSEEK_API_KEY=...
NVIDIA_API_KEY=...
KIMI_API_KEY=...
MINIMAX_API_KEY=...       # 或 MINIMAX_CN_API_KEY（中国区）
ZAI_API_KEY=...           # 或 GLM_API_KEY（智谱）
DASHSCOPE_API_KEY=...     # 阿里通义
```

完整供应商与端点对照见 [04 · 模型与提供商](./04-模型与提供商.md)。

### 工具 Key（部分）

```bash
EXA_API_KEY=...           # 网页搜索
FIRECRAWL_API_KEY=...     # 网页抓取
TAVILY_API_KEY=...
BRAVE_SEARCH_API_KEY=...
FAL_KEY=...               # 图像生成
ELEVENLABS_API_KEY=...    # 高级 TTS / 转写
BROWSERBASE_API_KEY=...   # 云浏览器
GITHUB_TOKEN=...          # GitHub API / Skills Hub 限额
HONCHO_API_KEY=...        # Honcho 长期记忆
```

### 消息平台 Token（部分）

```bash
TELEGRAM_BOT_TOKEN=...
DISCORD_BOT_TOKEN=...
SLACK_BOT_TOKEN=...       # 还需 SLACK_APP_TOKEN
FEISHU_APP_ID=...         # 还需 FEISHU_APP_SECRET
DINGTALK_CLIENT_ID=...    # 还需 DINGTALK_CLIENT_SECRET
```

各平台完整连接方式见 [05 · 消息网关与平台连接](./05-消息网关与平台连接.md)。

> **不要把非密钥设置塞进 `.env`**。像 `MESSAGING_CWD`、`.env` 里的 `TERMINAL_CWD` 已被废弃；工作目录请用 `config.yaml` 的 `terminal.cwd`。

## 3. 三个配置加载器

知道自己处在哪条加载路径很重要（否则会出现「CLI 看得到、网关看不到」）：

| 加载器 | 谁用 | 位置 |
|--------|------|------|
| `load_cli_config()` | CLI 模式 | `cli.py`（合并 CLI 默认 + 用户 YAML）|
| `load_config()` | `hermes tools`、`hermes setup` 等多数子命令 | `hermes_cli/config.py`（合并 `DEFAULT_CONFIG` + 用户 YAML）|
| 直接读 YAML | 网关运行时 | `gateway/run.py` + `gateway/config.py` |

新增键时若 CLI 能看到、网关看不到（或反之），多半是加载器/`DEFAULT_CONFIG` 覆盖问题。

## 4. 多 Profile（隔离的多实例）

Hermes 的所有路径都通过 `hermes_constants.get_hermes_home()` 解析，因此可以跑**完全隔离**的多个实例——各有独立的配置、会话、技能、记忆、检查点。

### 用 `HERMES_HOME` 切换

```bash
# 实例 A：写代码（用 Claude Opus）
HERMES_HOME=~/.hermes/profiles/coder hermes

# 实例 B：做研究（用 Gemini）
HERMES_HOME=~/.hermes/profiles/research hermes
```

每个 Profile 目录下都有自己独立的 `config.yaml`、`.env`、`state.db`、`skills/`、`logs/` 等。

### 关键点

- `get_hermes_home()` 先读 `HERMES_HOME` 环境变量，否则回退到 `~/.hermes`。
- 当前激活 Profile 记录在 `~/.hermes/active_profile`。
- **派生子进程**（网关、kanban 调度器、定时任务）时必须显式把 `HERMES_HOME` 传进环境，否则可能落到错误的 home。
- `HERMES_HOME`、`HERMES_PROFILE`、`HERMES_CONFIG`、`HERMES_ENV` 这几个变量不能通过仪表盘的 env 写入器修改——必须手动编辑或用命令行设置。
- 用 `/profile` 查看当前 Profile 名与目录。
