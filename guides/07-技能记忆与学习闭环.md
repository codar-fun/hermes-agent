# 07 · 技能、记忆与学习闭环

Hermes 最大的特色是一条**闭环学习链**：它把经验沉淀为可复用的「技能」、维护长期记忆、检索自己的历史会话，并在后台自动维护这些知识。

---

## 1. 技能（Skill）—— 程序性记忆

技能是 `~/.hermes/skills/<类别>/<名字>/SKILL.md` 下的 **Markdown 手册**（带 YAML frontmatter），可附带 `references/`、`templates/`、`scripts/`、`assets/`。它既是给模型看的操作指南，也能被用户用 `/<技能名>` 当斜杠命令直接调用。

### 管理技能

```text
/skills              # 搜索、安装、查看、管理技能
/<技能名>            # 直接调用某技能（如 /deepscan、/code-review）
/bundles             # 列出技能捆绑包（一个别名对应多个技能）
/reload-skills       # 重新扫描技能目录（装了新技能后）
```

### 技能的结构

```
skills/research/some-skill/
├── SKILL.md            # YAML frontmatter + Markdown 指令
├── references/         # 参考资料
├── templates/          # 模板
├── scripts/            # 可执行脚本
└── assets/             # 静态资源
```

`SKILL.md` 的 frontmatter 字段：`name`（≤64 字符）、`description`（≤1024 字符，决定何时被召回）、`version`、`platforms`（macos/linux/windows）、`prerequisites`、`metadata.hermes.tags`。

> 渐进式披露：`skills_list` 只返回元信息（省 token），`skill_view` 才加载完整指令和关联文件。

### 自我改进（self-improving loop）

- 智能体可以**自己创建/编辑/打补丁/删除**技能（`skill_manage` 工具：create / edit / patch / delete / write_file）。
- 完成复杂任务后，后台会评估「要不要把这次做法存成技能」（见下文 Curator 与后台复盘）。
- 这就是「从经验中学习」：成功的做法被固化为可复用知识。

## 2. Skills Hub —— 安装第三方技能

Skills Hub 让你从 GitHub 或官方可选技能库安装技能（`tools/skills_hub.py`），并兼容 [agentskills.io](https://agentskills.io) 开放标准。

- **来源**：任意 GitHub 仓库（Contents API）、随仓库附带但默认不激活的 `optional-skills/`（95 个）。
- **信任级别**：builtin（内置）/ trusted（官方）/ community（社区）。
- **安全**：安装前做 AST 审计与隔离（quarantine）；记录来源锁（`~/.hermes/skills/.hub/lock.json`）与审计日志（`audit.log`）；可加自定义 hub 源（taps）。
- **路径校验**：防 `../..` 穿越、绝对路径、空路径。

> 仓库自带 74 个内置技能（`skills/`）+ 95 个可选技能（`optional-skills/`），覆盖软件开发、研究、运维、创意、社媒、邮件、智能家居等类别。

## 3. 长期记忆

Hermes 跨会话记住事实，分两类（受 `config.yaml` 的 `memory` 段控制）：

| 类型 | 文件 | 默认上限 | 内容 |
|------|------|----------|------|
| 智能体笔记 | MEMORY.md | `memory_char_limit: 2200`（约 800 token）| 智能体自己记的事 |
| 用户画像 | USER.md | `user_char_limit: 1375`（约 500 token）| 关于「你是谁」的理解 |

```yaml
memory:
  memory_enabled: true
  user_profile_enabled: true
  nudge_interval: 10        # 每 10 回合提醒一次保存记忆
```

- **`memory` 工具**：智能体读写持久记忆；由智能体循环在 `handle_function_call` 之前拦截处理。
- **周期性提醒（nudge）**：每隔若干回合提醒智能体「该不该把某事存进记忆」。

### 外部记忆后端（可插拔）

除内置的本地记忆外，可接入外部记忆提供商（同时只允许一个外部提供商）：**honcho、mem0、supermemory、byterover、hindsight、holographic、openviking、retaindb**。它们实现 `agent/memory_provider.py` 的 `MemoryProvider` 抽象基类，由 `agent/memory_manager.py` 编排（`prefetch` 回合前取、`sync_turn` 回合后写）。

```bash
hermes memory setup           # 配置记忆提供商
# Honcho（对话式用户建模）示例：
hermes honcho setup
hermes honcho status
hermes honcho mode [hybrid|honcho|local]
```

> 注意：内置记忆提供商集合已**封闭**——新后端请作为独立插件仓库发布到 `~/.hermes/plugins/`，实现同一 ABC 即可，不再往 `plugins/memory/` 里加。

## 4. 会话检索（跨会话回忆）

所有会话都存进 `~/.hermes/state.db`（SQLite + FTS5 全文检索，schema v14）。

- **`session_search` 工具**：检索并用 LLM 摘要回忆过去的对话（`tools/session_search_tool.py`）。
- **`hermes sessions browse`** / **`/sessions`**：带搜索的会话选择器。
- 压缩触发的会话拆分通过 `parent_session_id` 链记录；会话按来源打标签（cli/telegram/…）便于过滤。

## 5. Curator —— 后台技能自维护

Curator 是后台进程，在空闲时复盘智能体创建的技能并自动管理其生命周期（`agent/curator.py`）。

```text
/curator status         # 查看状态
/curator run            # 立即跑一次
/curator pin <技能>     # 钉住（不被归档）
/curator archive        # 归档
/curator list-archived  # 列出已归档
```

```yaml
curator:
  enabled: true
  interval_hours: 168       # 每 7 天
  min_idle_hours: ...       # 至少空闲多久才跑
  stale_after_days: 30      # 多久未用标记 stale
  archive_after_days: 90    # 多久未用归档
  backup: {...}             # 运行前快照（curator_backup.py）
```

- 运行前会把技能树打包快照到 `~/.hermes/skills/.curator_backups/<UTC时间>/`，可回滚。
- **后台复盘**（`agent/background_review.py`）：每回合后派生一个工具受限的智能体，决定是否保存记忆 / 创建或改进技能——这是学习闭环的「写入」端。

## 6. 用量洞察

```text
/insights [--days N]    # 用量分析：token 消耗、成本估算、工具使用模式、活跃趋势
/usage                  # 当前会话 token 用量与速率限制
```

数据来自 `state.db`，由 `agent/insights.py` 汇总（灵感来自 Claude Code 的 `/insights`）。
